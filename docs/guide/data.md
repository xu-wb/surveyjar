# 保存、备份与迁移

Git 同步程序，数据库保存研究内容。两者需要分别管理。

## 保存位置

| 内容 | 保存位置 | Git 同步 |
| --- | --- | --- |
| 正式问卷、项目、批次、答卷、作答草稿 | `data/questionnaires.sqlite3` | 不上传 |
| 尚未正式保存的编辑器草稿 | 当前浏览器 localStorage | 不上传 |
| 未写入完成的作答恢复副本 | 当前浏览器 localStorage | 不上传 |
| 个人材料与研究记录 | `local/` | 不上传 |
| 程序、通用模板与文档 | 项目源码 | 上传 |

填写草稿约 600 毫秒自动保存一次。界面显示「保存失败」时，保持页面打开并检查服务窗口。不要同时在多个标签编辑同一份草稿。

## 备份

1. 在编辑器中正式保存需要保留的问卷。
2. 确认作答已保存，然后关闭服务窗口。
3. 将 `data/` 复制到独立备份位置；需要保留个人材料时同时复制 `local/`。

仅备份数据库时，关闭服务后复制 `data/questionnaires.sqlite3` 即可。浏览器中尚未正式保存的编辑器草稿不包含在数据库备份里。

## 恢复与换电脑

新电脑先准备程序与 Python 环境，在服务关闭时放回备份的 `data/`，需要时同时放回 `local/`，然后启动工具。

恢复已有电脑时，先另存当前数据库，再用备份替换。替换数据库会切换到备份时的记录。

## 更新程序

关闭工具并备份数据，在原项目目录执行：

```sh
git pull --ff-only
```

更新程序通常保留被 Git 忽略的 `data/` 和 `local/`。不要通过删除整个项目目录重新下载来更新，也不要运行会清除忽略文件的 `git clean -fdx`。

## 数据访问范围

服务仅监听 `127.0.0.1`，本机写接口检查请求来源。数据库没有加密，工具没有研究人员账号与访问权限管理；应使用操作系统账户、文件权限和备份位置管理数据。

Git 的上传排除规则位于项目根目录 `.gitignore`。它控制上传范围，不代替备份或加密。
